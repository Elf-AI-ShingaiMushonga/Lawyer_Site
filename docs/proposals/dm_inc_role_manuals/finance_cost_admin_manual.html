This guide is for the finance and cost admin role that owns billing, trust, expenses, reporting, and a significant share of the platform’s administrative control surfaces.

Role posture

Finance / cost admin is one of the most powerful roles in the current implementation. It combines revenue and trust authority with admin-family access, which means it should be assigned narrowly and trained carefully.

Finance / Cost Admin Role

Own the revenue, trust, and financial-control loop while protecting platform governance.

This role sits at the center of commercial discipline. It should make sure time becomes invoices, invoices become collections, trust stays controlled, expenses are auditable, and financially sensitive changes remain visible and governed.

Billing Cycle

The billing loop should run as one connected process from time review to collection posture.

If billing surfaces are used in isolation, leakage grows. Finance / cost admin should use the module set as one sequence rather than a set of unrelated reports.

Core billing rhythm

  1. 1
    Review time first.
    Use Time Review and invoice preparation surfaces to make sure time is approved, clean, and ready to convert.
  2. 2
    Generate and review invoices.
    Use invoice lists, invoice detail, approvals, adjustments, PDF and tax output where needed.
  3. 3
    Track collections actively.
    AR Aging, account statements, transactions, and matter-level billing posture should show where cash movement is stuck.
  4. 4
    Keep supporting financial records current.
    Expenses, payment settlement, and audit-log review should sit inside the same cadence.

Main billing screens

  • Billing Rates: control rate cards and pricing inputs.
  • Billing Invoices and invoice detail: review, adjust, approve, export, and issue output.
  • AR Aging: track overdue debtor exposure.
  • Transactions and audit log: see movement, status, and change history.
  • Expenses: capture, approve, and preserve receipts and summaries.

Trust Cycle

Trust accounting requires deliberate, reportable rhythm and strong change discipline.

The trust module set is broad enough to support day-to-day operations and reporting, but only if the role uses it as a controlled cycle rather than isolated posting screens.

Core trust surfaces

  • Trust Ledger: transaction and approval posture.
  • Reconciliations: structured trust balancing and control checks.
  • Cashbook: operational view of trust cash activity.
  • Section 86: the specific trust reporting and import flow.
  • Monthly, trial balance, and auditor reports: reporting and external-control surfaces.

Trust operating principles

  • Post accurately and review quickly.
  • Do not let reconciliation become retrospective archaeology.
  • Keep report readiness continuous.
  • Use approval and audit trails deliberately.
  • Escalate anomalies immediately, especially where client funds are affected.
Trust activity is one of the most sensitive domains in the system. Finance / cost admin should operate with a named control cadence, dual review where appropriate, and explicit escalation paths for anomalies or exceptions.
Admin and Governance

This role is not only about money. It is also a governance role in the current build.

Finance / cost admin belongs to the admin family. That means user, portal, settings, and audit surfaces may sit inside the same login. That convenience must be paired with strong governance habits.

Governance surfaces this role may touch

  • Admin Command Center and audit log for sensitive platform changes.
  • Portal User Administration where client identity and matter visibility need management.
  • Firm settings and rates where commercial and metadata configuration affects the live environment.
  • Templates, rules, and automation surfaces where operating logic changes can affect legal and financial outputs.

Guardrails for this role

  • Document material control changes.
  • Separate operational finance work from platform-governance work mentally and procedurally.
  • Do not treat admin power as routine back-office convenience.
  • Review audit trails and transaction history as part of the role, not as a one-off exercise.
Practical governance note: this role should be assigned only to trusted finance leadership or named platform administrators. The current implementation gives it meaningfully broader authority than a narrow “billing clerk” interpretation would imply.
Checklist

Finance / cost admin is ready when the commercial cycle becomes controlled, repeatable, and auditable.

Operational readiness checklist

  • Can run time review to billing conversion cleanly.
  • Can review and issue invoices with confidence.
  • Can monitor AR and transaction posture without separate spreadsheets.
  • Can operate trust ledger, reconciliation, and reporting surfaces properly.
  • Can explain what changed through audit and transaction history.

Month-end / control checklist

  • Billing leakage reviewed.
  • Invoice approvals and settlements current.
  • AR Aging reviewed with clear follow-up owners.
  • Trust reconciliation and report posture current.
  • Any admin or portal changes logged and understood.
