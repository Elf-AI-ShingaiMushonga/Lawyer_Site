Pack Overview

A role-based operating manual set for the full DM-Inc platform.

The manuals in this folder are designed for training, onboarding, executive review, and go-live support. They map each role to the screens it uses most, the workflows it owns, the controls it must respect, and the escalations it should trigger when work falls outside its remit.

What these manuals are for

  • Training: give each user group a practical explanation of how they should run the platform.
  • Demonstrations: help DM-Inc present the system in a credible, role-specific way.
  • Onboarding: shorten the time between account creation and productive day-one use.
  • Governance: make role boundaries explicit before go-live authority becomes messy.

How to read them

  • Start at the top: each manual opens with the role’s remit and access posture.
  • Follow the workflow sections: these are arranged around the daily operating rhythm for the role.
  • Use the guardrails: every manual includes limits, approval points, and high-risk actions.
  • Use the checklists: the closing slide of each deck is designed for live training and cutover preparation.

Common navigation conventions

  • Dashboard first: most users should begin with the dashboard and use workspace mode to launch into work.
  • Matter centricity: once a matter is opened, related tasks, notes, DMS, calendar, and billing flows are easier to access in context.
  • Search as a cross-cutting tool: the Search Command Center is often the fastest route when the user knows the record but not the module.
  • Portal collaboration is split: internal users work in the client message center and portal admin surfaces, while external users stay in the client portal.

Cross-cutting themes in the manuals

  • Role remit: what the role is expected to own operationally.
  • System access: what the application currently exposes to that role family.
  • Guardrails: which actions are high-impact and should stay tightly controlled.
  • Practical rhythm: what the role should do daily, weekly, and at key control points such as billing or cutover.
Governance Rules

The operating constraints that matter across every manual.

These constraints are central to how the role manuals should be interpreted. They are more important than broad labels such as “full access” or “read only”, because they explain the real operating boundaries in the application.

Rules that apply to internal users

  • Matter membership still governs visibility. Being a lawyer or administrator does not erase the need for matter-team inclusion, except where admin scope explicitly expands visibility.
  • Ethical walls still override convenience. A user can be blocked from a matter even if they otherwise sit in a role family with access to that module.
  • Workspace mode is not a permission system. It changes dashboard quick actions and launch emphasis; it does not by itself re-authorize the user.
  • MFA matters most for privileged roles. Admin-family and operations staff roles are expected to operate with stronger access hygiene.

Rules that matter in client collaboration

  • Portal access is separately granted per matter. A portal user can have different visibility levels on different matters.
  • Portal messaging needs thread discipline. Internal and external users should stay inside existing threads when the topic is unchanged.
  • Uploads and secure links are controlled surfaces. They are not general-purpose file dumps and should stay matter-linked and auditable.
  • The finance / cost admin role is powerful. It should be treated as a trusted control role, not just a clerical billing role.
Current implementation note: senior and junior attorney roles share the same broad route-level legal, DMS, CRM, and billing permissions in the application. DM-Inc should still enforce internal working policy to decide which attorneys are expected to use approval-heavy or governance-heavy actions in day-to-day practice.
Recommended Rollout

A practical training sequence for using the manuals during onboarding and go-live.

The order below is built to stabilize control roles first, then legal execution roles, then support and external collaboration. That sequence usually reduces noise during the first live operating week.

Recommended sequence

  1. 1
    Director and finance / cost admin first.
    They shape governance, user setup, revenue controls, portal administration, and escalation posture.
  2. 2
    Senior and junior attorneys second.
    These users drive the main legal operating loop and should stabilize matter execution early.
  3. 3
    Candidate attorneys third.
    They need strong procedural guidance once the supervising patterns are already clear.
  4. 4
    Operations staff fourth.
    Support workflows should be trained against a realistic live platform footprint rather than an abstract one.
  5. 5
    Client portal users last.
    External collaboration training is easiest once internal portal handling and matter governance are settled.

What “comprehensive” should mean in practice

  • Do not train by module only. Train by real task flow such as “open a matter, draft, log time, send a client reply”.
  • Use the manuals during live demos. Each deck is structured so you can present from it and then pivot into the actual application.
  • Keep a decision log. When the role manual and DM-Inc internal practice differ, document the chosen operating rule rather than relying on memory.
  • Refresh after UAT or scope changes. These manuals are comprehensive for the current build, not a permanent substitute for release notes.
